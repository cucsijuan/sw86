Contents

What COS Is

COS, the CucsiCorp Operating System, is the disk operating system for the pc86 personal computer. It is the program that looks after the computer for you: it keeps your programs and information in files on diskettes, starts your programs, gives them the memory and the files they ask for, and lets you copy, rename, display and erase files with simple commands.

COS has two parts:

COS.SYSThe operating system itself. It is read from the diskette when you start the computer and stays in memory all the time. Programs ask it for services through interrupt 21h.
COMMAND.COMThe command processor. It shows the prompt, reads what you type and carries out your commands. It is an ordinary program: if it ever ends, COS starts it again.

A small third part, the boot record, lives in the first sector of the System Diskette. It is what the computer reads first; its only job is to find COS.SYS on the diskette and start it.

What You Need

  • A pc86 personal computer, with the 8086 microprocessor and 640 KB of memory.
  • A video card and a monitor. COS uses the 80-column text mode.
  • A keyboard.
  • A diskette adapter with one or two 3½-inch diskette drives. The first drive is drive A:, the second drive B:.
  • The COS System Diskette, and blank formatted diskettes for your own work. COS reads and writes 1.44 MB (high density) and 720 KB (double density) diskettes.

The computer must boot from drive A:. The System Diskette goes in drive A:; drive B:, if you have one, holds a second diskette, usually the one with your work.

What COS Can Do

  • Run programs: .COM and .EXE files, one at a time, with up to 583 KB of memory for each program.
  • Keep files on diskettes, in directories: up to 224 files in the main directory of a 1.44 MB diskette (112 on a 720 KB diskette), and as many as fit in the directories you make inside it, each file up to the size of the diskette.
  • Copy, rename, erase and display files, and list what is on a diskette.
  • Keep the date and the time of day, and record them on every file you write.
  • Notice when you change the diskette in a drive, and tell you when a diskette cannot be read or written.

COS provides the services of the version 3.30 disk operating system that programs most often use, with the same function numbers, so that programs written for those services run without change. Chapter 8 lists what COS leaves out.

How to Use This Manual

Starting COS

  1. Insert the COS System Diskette in drive A:, label side up.
  2. Turn on the monitor, then the computer. If the computer is already on, press its Reset button.

The computer tests itself, reads the boot record from the diskette, and the boot record loads COS. After a moment you see:

CucsiCorp COS Version 1.00
(C) Copyright CucsiCorp 1981
A:\>

COS is now ready for your commands. If instead you see one of the following, the computer could not start COS:

No boot device available.There is no diskette in drive A:, or no diskette adapter. Insert the System Diskette and press Reset.
The diskette in drive A: is not bootable.The diskette in drive A: has no boot record. It is not a System Diskette.
Non-system diskThe diskette is formatted but has no operating system. Replace it with the System Diskette and press any key.
COS.SYS is missingThe diskette has the COS boot record but not COS.SYS. Use another System Diskette.
Disk errorThe diskette could not be read. Try again; if it fails again, the diskette is damaged.

Type a command after the prompt and press Enter. Nothing happens until you press Enter, so you can correct mistakes first:

Entering the Date and Time

The computer has no battery clock. Each time you start COS, the date is set to Tuesday, 1 January 1980, and the time to midnight. COS records the date and time on every file you write, so set them first with the DATE and TIME commands:

A:\>date
Current date is Tue  1-01-1980
Enter new date (mm-dd-yy): 10-14-81

A:\>time
Current time is  0:00:00.32
Enter new time: 9:30

The time is kept on the 24-hour clock: type 13:15 for a quarter past one in the afternoon. To keep the date or time shown, just press Enter.

Stopping a Program

Press Ctrl-C to stop a program while it is waiting for you to type something. COS ends the program and shows the prompt. A program that never reads the keyboard cannot be stopped this way; press the computer's Reset button to start again.

Turning Off the Computer

Before you turn off the computer or remove a diskette, wait until the prompt is displayed and the drive light is out. COS writes some information to the diskette only when a program finishes with a file; removing the diskette before that may leave the file incomplete.

Files

Everything COS keeps on a diskette is kept in files. A program is a file; a letter, a list or a game's high scores is a file. Every file has a name, and every diskette has a directory, a list of the files on it with their names, sizes and dates.

File Names

A file name has two parts: the filename, one to eight characters, and an optional extension of up to three characters, separated by a period:

LETTER.TXT      filename LETTER, extension TXT
COMMAND.COM     filename COMMAND, extension COM
SCORES          no extension

The characters you can use are the letters A to Z, the digits 0 to 9, and these special characters:

$ & # @ ! % ' ( ) - { } ~ ` ^ _

Small letters are changed to capitals, so letter.txt and LETTER.TXT are the same file. Extra characters are ignored: CORRESPONDENCE.TEXT is the file CORRESPO.TEX.

Extensions

The extension usually says what kind of file it is. COS gives these extensions a meaning:

.COMA program, in the simple .COM form (up to 64 KB).
.EXEA program, in the .EXE form, which may be larger and use several segments.
.SYSPart of the operating system: COS.SYS.
.BATA batch file. COS Version 1.00 does not run batch files.

Other common extensions are .TXT for text, .ASM for assembly language programs and .DAT for data, but you may use any extension you like.

File Specifications

To name a file on a drive other than the default drive, put the drive letter and a colon in front of it. This is a file specification:

B:LETTER.TXT

A file specification can also say which directory the file is in, B:\LETTERS\JUNE.TXT. Directories are explained below.

Reserved Names

Some names stand for devices, not files, and cannot be used as filenames, with any extension:

CONThe console: the keyboard for input, the display for output.
NULA dummy device: what is written to it disappears, and reading from it gives an immediate end of file.
AUX, PRN, COM1, COM2, LPT1, LPT2, CLOCK$Serial, printer and clock devices. The pc86 computer does not have them; opening them is refused ("Access denied").

For example, copy readme.txt con would display the file, as TYPE does.

Global Filename Characters

Two characters, ? and *, let one file specification stand for several files. They are called global filename characters, or wildcards.

The ? Character

A ? in a filename or extension matches any character in that position:

DIR REPORT?.TXT     lists REPORT1.TXT, REPORT2.TXT, REPORTA.TXT ...

The * Character

An * matches any characters from its position to the end of the filename or the extension:

DIR *.TXT           every file with the extension TXT
DIR R*.*            every file whose name begins with R
COPY *.* B:         every file, to drive B:

DIR, COPY, DEL and REN accept global characters. Other commands, and programs you run, need a single file name.

Directories

A diskette with many files is easier to use when they are kept in groups. COS lets you make directories for them, the way a filing cabinet has folders: one for your letters, one for your games, one for a program you are writing.

Every diskette starts with one directory, the root directory. You can make directories in it, and directories in those, as many as you like. A directory has a name like a file (eight characters, and an extension if you wish), and appears in the listing of the directory that holds it as <DIR>:

Paths

A path names a directory by the directories that lead to it, separated by backslashes (\). A path that starts with a backslash starts at the root directory; any other starts at the current directory. .. goes up one level:

\GAMES\SPACE.COMSPACE.COM in the directory GAMES of the root directory.
GAMES\SPACE.COMThe same, if the root directory is the current directory.
..\NOTES.TXTNOTES.TXT in the directory above the current one.
B:\LETTERSThe directory LETTERS on the diskette in drive B:.
B:JUNE.TXTJUNE.TXT in the current directory of drive B:.

Every command that takes a file name takes a path too: type \letters\june.txt, copy *.com games, del b:\old\*.*. A path may be up to 63 characters long.

When the diskette in a drive is changed, the current directory of that drive goes back to the root directory.

Preparing Diskettes

COS works with diskettes that have been formatted: prepared with tracks, sectors, an empty directory and a file allocation table. COS Version 1.00 does not format diskettes itself: use the formatted blank diskettes supplied for the pc86, or a diskette COS has already used, after erasing its files with DEL *.*. To make a new System Diskette, copy COS.SYS, COMMAND.COM and the programs you want onto a diskette that already has the COS boot record, such as a copy of your System Diskette.

Write Protection

A diskette has a write-protect tab. When the tab is open, COS can read the diskette but cannot change it, so files on it cannot be erased by mistake. If you try to write to a protected diskette, COS says:

A:\>copy letter.txt b:

Write protect error writing drive B
Abort, Retry, Fail?F
File creation error
        0 File(s) copied

Close the tab and type R to retry, or type F to give up. Chapter 5 explains the three answers.

Caring for Diskettes

  • Keep diskettes away from magnets, heat and direct sunlight.
  • Do not open the metal shutter or touch the surface of the diskette.
  • Remove diskettes from the drives only when the drive light is out.
  • Keep a copy of every diskette that holds work you cannot do again.

Volume Labels

A diskette may have a name of up to 11 characters, its volume label, written when it is formatted. DIR and VOL display it. Use labels to tell your diskettes apart.

COPY

Purpose
Copies one or more files, to the same diskette with another name or to another diskette.
Format
COPY [d:]filename[.ext] [d:][filename[.ext]]
Remarks

The first file specification is the source; it may contain global characters. The second is the target:

  • If the target is only a drive, B:, the copies get the same names on that drive.
  • If the target is a name, the copy gets that name. With global characters in the target, each ? or * keeps the corresponding characters of the source name: COPY *.TXT B:*.BAK.
  • If there is no target, the copy goes to the default drive with the same name.

When the source has global characters, COPY displays the name of each file as it copies it. At the end it tells you how many files it copied. A file that already exists on the target diskette is replaced.

The copy is exact, byte for byte, and keeps the date and time of the original. A file cannot be copied onto itself. If the target diskette fills up, the incomplete copy is erased and COPY says "Insufficient disk space".

Example
A:\>copy letter.txt b:note.txt
        1 File(s) copied

A:\>copy *.com b:
A:COMMAND.COM
A:ASM.COM
A:EDIT.COM
A:HELLO.COM
A:NUMBERS.COM
A:FACTOR.COM
A:SORT.COM
        7 File(s) copied

Running Programs

A word at the prompt that is not a command is the name of a program:

[d:][path]filename[.ext] [parameters]

COS looks in the directory you name, or in the current directory, for filename.COM and then for filename.EXE, and runs the first one it finds. If you type the extension, only that file is tried. When you give only a name and the program is not in the current directory, COS looks for it in the root directory of the drive as well, so the programs of the System Diskette (EDIT, ASM) can be used from any directory. The rest of the line, the parameters, is given to the program exactly as you typed it.

If there is no such program, COS says "Bad command or file name". If there is not enough memory for it, "Program too big to fit in memory". If only a batch file (.BAT) has that name, "Batch files are not supported by COS".

When the program ends, its memory is given back and the prompt returns. The files it left open are closed.

Introduction

This chapter is for programmers. It explains how programs are written for COS, how COS loads and runs them, and how a program asks COS for its services. It assumes you know the 8086 processor and its assembly language.

A program asks for a service by loading a function number into register AH, and the other parameters into other registers, and executing an INT 21h instruction. COS does the work and returns, with results in registers. When a function fails, COS sets the carry flag (CF) and puts an error code in AX. Chapter 7 describes every function; Appendix A lists the error codes.

Tools

COS programs are written in 8086 assembly language. Everything you need is on the System Diskette:

  1. Write the program with the editor: EDIT GAME.ASM (Chapter 9).
  2. Assemble it: ASM GAME makes GAME.COM (Chapter 10).
  3. Run it: GAME.

COS itself is written in the same language, and ASM assembles it: Chapter 10 shows how. COS.SYS can be anywhere on the System Diskette; the boot record finds it in the directory.

Your First Program

This program displays a message and ends:

; hello.asm - the classic: print a string with COS service 09h
org 100h

    mov dx, message     ; DS:DX points to the text
    mov ah, 09h         ; "display a string ending in $"
    int 21h
    ret                 ; a .COM program may end with RET

message db 'Hello from the 8086!', 13, 10, '$'

Assembled, it is a .COM file of 31 bytes. Run it by typing HELLO.

Ending a Program

A program ends with one of these:

MOV AX,4C00h / INT 21hThe best way. AL is a return code (0 means success) that the parent can read with function 4Dh.
INT 20hCS must point to the PSP. Return code 0.
RETIn a .COM program, with the stack as it was at the start: the word 0 at the top of the stack sends it to the INT 20h at the start of the PSP.

When a program ends, COS closes its files, frees its memory, restores interrupt vectors 22h, 23h and 24h, and returns to the program that started it.

.COM Programs

A .COM file is an image of the program: COS copies it into memory at offset 100h of a segment and jumps to it. The program must be assembled with ORG 100h and fit in 64 KB less 256 bytes for the PSP and the stack (the largest .COM file is 65,280 bytes).

At the start of a .COM program:

CS, DS, ES, SSThe segment of the program segment prefix (PSP).
IP0100h.
SPFFFEh, or the top of the memory given to the program if that is less than 64 KB. A word of 0 is on the stack.
AX0000h. (BX = 0, CX = 00FFh, DX = PSP segment, SI = DI = BP = 0.)
FlagsInterrupts enabled.
MemoryThe largest free block of memory belongs to the program.
DTAPSP:0080h.
Because a .COM program owns the largest block of memory, it must give back what it does not need with function 4Ah before it can allocate memory with function 48h or run another program with function 4Bh.

.EXE Programs

An .EXE file begins with a header that tells COS how big the program is, where its stack and its first instruction are, and which words must be adjusted for the segment it is loaded at (the relocation table). An .EXE program may be larger than 64 KB and use several segments.

The Environment

The environment is a block of memory of strings in the form NAME=value, each ending with a zero byte, with an extra zero after the last one. A word 0001h and the full name of the program, such as A:\GAME.COM, follow it. The segment of the environment is at offset 2Ch of the PSP. Under COS it holds:

COMSPEC=A:\COMMAND.COM

Memory

The memory COS does not use itself is divided into blocks, each preceded by a 16-byte memory control block (MCB): a byte 'M' (or 'Z' for the last block), the segment of the PSP that owns the block (0 if it is free), and the size of the block in paragraphs. A program allocates, resizes and frees blocks with functions 48h, 4Ah and 49h; COS gives the first free block that is large enough. All the blocks a program owns are freed when it ends, unless it ends with function 31h (terminate and stay resident).

With COMMAND.COM loaded, the largest block a program can have is 91E2h paragraphs: 597,536 bytes. Chapter 8 shows how memory is used.

Files and Handles

A program uses files through handles: small numbers that COS gives it when it opens or creates a file (functions 3Dh and 3Ch), and that it then uses to read (3Fh), write (40h), move (42h) and close (3Eh) the file. Every program starts with three handles open:

HandleNameDevice
0Standard inputCON (the keyboard)
1Standard outputCON (the display)
2Standard errorCON (the display)

A program may have 20 handles open at once, and COS 20 files for all programs together. A program started with function 4Bh inherits its parent's open handles, so it writes to the same standard output.

Reading from the console through handle 0 is cooked: COS reads a whole line with editing, as function 0Ah does, and returns it followed by a carriage return and a line feed. Function 4401h can set the console to raw mode, in which each key is returned as it is pressed, without echo.

COS writes a file's data to the diskette when the program closes the file (3Eh) or commits it (68h), at disk reset (0Dh), when the program ends, and whenever it needs to read another track of the diskette. A program that keeps a file open for a long time should commit it from time to time.

Example: Writing a File

    mov ah, 3Ch             ; create SCORES.DAT
    mov dx, name
    xor cx, cx              ; normal attributes
    int 21h
    jc error                ; CF set: AX = error code
    mov bx, ax              ; the handle
    mov ah, 40h             ; write 4 bytes
    mov dx, scores
    mov cx, 4
    int 21h
    jc error
    mov ah, 3Eh             ; close: the data reaches the diskette
    int 21h
    ...
name   db 'SCORES.DAT', 0
scores db 10, 20, 30, 40

Errors

Handle functions and most other functions report an error by setting the carry flag and returning an error code in AX: always test CF after INT 21h. Function 59h returns the code of the last error again. Appendix A lists the codes.

Disk errors are reported to the user first, by the critical error handler, which asks "Abort, Retry, Fail?". If the user answers F, the function returns error 83 (53h). A program can install its own critical error handler at INT 24h; Chapter 8 describes how it is called.

Ctrl-C

When the user presses Ctrl-C while a program waits in a console input function (01h, 08h, 0Ah, 0Bh, or a cooked read of handle 0), COS displays ^C and executes INT 23h. The default handler ends the program. A program may install its own handler with function 25h:

  • If the handler returns with IRET, COS carries out the function again.
  • The handler may also end the program, or jump to a safe place in it after resetting its stack.

COS restores INT 23h when the program ends. Functions 06h and 07h do not check for Ctrl-C; a program that reads keys with them sees Ctrl-C as the character 03h.

Running Another Program

Function 4Bh, EXEC, loads and runs another program and returns when it ends. The caller passes the program's name and a parameter block:

    mov ah, 4Ah             ; first, give back unused memory
    mov bx, (program_end - $$ + 100h + 15) / 16
    int 21h
    mov dx, child           ; DS:DX = name
    mov bx, block           ; ES:BX = parameter block
    mov [block+4], cs
    mov [block+8], cs
    mov [block+12], cs
    mov ax, 4B00h
    int 21h
    jc failed
    mov ah, 4Dh             ; the child's return code
    int 21h
    ...
child db 'CHILD.COM', 0
tail  db 7, ' hello!', 13
block dw 0                  ; environment: a copy of ours
      dw tail, 0            ; command tail
      dw 5Ch, 0             ; first FCB
      dw 6Ch, 0             ; second FCB

All registers are kept across the call. The DTA is set to the caller's PSP:0080h.

Terminate and Stay Resident

A program can end and leave part of itself in memory, for example an interrupt handler, with function 31h (or INT 27h). DX gives the number of paragraphs to keep, counted from the PSP; the rest is freed. Open files are not closed.

The Processor

The pc86 computer's 8086 executes every 8086 instruction except these, which stop the computer with an error instead of doing something different: the decimal adjust instructions (DAA, DAS, AAA, AAS, AAM, AAD), XLAT, LOCK, WAIT, ESC, INTO, and undocumented instructions. Avoid them in COS programs.

Rules for Well-Behaved Programs

  • Use the COS functions for the keyboard, the display and files; use the BIOS (Appendix D) for what COS does not do, such as moving the cursor or graphics.
  • Test the carry flag after every function that can fail.
  • Close every file you open, and end with function 4Ch.
  • Restore any interrupt vector you change, except 22h, 23h and 24h, which COS restores for you.
  • Do not call INT 21h from an interrupt handler or from a critical error handler: COS does not allow a function to be interrupted by another.

How COS Starts

  1. The BIOS reads sector 1 of the diskette in drive A: to 0000:7C00h and jumps to it with DL = 0.
  2. The boot record reads the BIOS parameter block in itself, loads the first file allocation table at 0000:7E00h, finds COS.SYS in the root directory and loads it at 0070:0000h, following its chain of allocation units. Then it jumps to it, with DL still the boot drive.
  3. COS.SYS counts the diskette drives (BIOS equipment word), sets interrupt vectors 20h to 2Fh, makes the memory control blocks up to the top of memory given by INT 12h, builds the master environment, and runs A:\COMMAND.COM with function 4Bh. If COMMAND.COM ever ends, COS runs it again.

The File Allocation Table

The file allocation table (FAT) has a 12-bit entry for every allocation unit, numbered from 2. An entry of 000h means the unit is free; FF8h to FFFh, that it is the last unit of a file; any other value, the number of the file's next unit. The entry of unit n is the word at byte n × 3 / 2 of the table: its low 12 bits if n is even, its high 12 bits if n is odd. COS keeps the whole table of each drive in memory and writes it to both copies on the diskette.

Disk Buffering

COS reads diskettes a whole track at a time into its track buffer: one turn of the diskette, a fifth of a second, brings in 18 sectors. Reads from the same track then need no diskette access.

Writes go into the buffer, and the sectors changed are written back together, in one operation, when COS needs another track, when a file is closed or committed, at disk reset, and when a program ends. A new directory entry (function 3Ch or 5Bh) and changes to the directory (41h, 43h, 56h) are written at once.

Before each use of a drive, COS asks the BIOS whether the diskette has been changed (INT 13h AH=16h). If it has, COS reads the new diskette's boot record and file allocation table.

Critical Errors

When a diskette operation still fails after three tries, COS calls INT 24h with:

AHBit 0: 0 reading, 1 writing. Bits 1-2: area (3 = data). Bit 3: Fail allowed. Bit 4: Retry allowed. Bit 7: 0 (a disk error).
ALDrive: 0 = A:, 1 = B:.

BP:SI0000:0000 (no device header).

The handler returns with IRET and AL = 1 to retry, 2 to abort (end the program), or 3 (or 0) to fail the function, which then returns error 83. The handler runs on COS's own stack and must not call INT 21h.

COS provides the version 3.30 services listed in Chapter 7, with the same numbers, registers and results. Programs that use only those services, through file handles, run on COS unchanged. COS Version 1.00 does not provide:

Introduction

A program for the 8086 is a sequence of instructions in machine code: bytes. Writing the bytes by hand is slow and full of mistakes, so programs are written instead in assembly language, where each instruction has a name (MOV, ADD, JMP) and each place in the program a label. ASM, the COS assembler, reads a program in assembly language from a text file, the source file, and writes the bytes, ready to run, to a .COM file.

COS itself, COMMAND.COM, EDIT and ASM are written in the language ASM accepts, and ASM can assemble all of them, itself included.

How ASM Works

ASM reads the source file once, a piece at a time, and keeps it in memory in a compact form, with every name looked up. Then it goes through the program several times, or passes. In each pass it works out the address of every line; a jump to a label further on may need 2 bytes or 3, depending on how far the label turns out to be, so the passes go on until no address changes. ASM always chooses the shortest form of each instruction. The last pass writes the bytes.

Assembling HELLO.ASM takes about a second. Larger programs take longer: COS.SYS, about 5,600 lines, takes about a minute. A source file can be of any size that fits on a diskette; the program it makes can be up to 64 KB.

The Source File

A source file is a text file. Each line holds at most one instruction or directive, in this order, each part optional:

label:    instruction   operands      ; comment
  • A label names the address of the line, so that other lines can use it. It starts with a letter, _, ?, @ or a period, and goes on with letters, digits and _ ? @ $ # ~ .; capital and small letters are different (Start and start are two labels). The colon may be left out when an instruction follows.
  • A label that starts with a period is local: it belongs to the last label before it without a period, so .loop after print: is really print.loop, and each routine can have its own .loop. A label that starts with two periods is not local.
  • The instruction is an 8086 instruction or a directive. Instruction names, register names and directives may be written in capital or small letters.
  • Operands are separated by commas.
  • A semicolon starts a comment: the rest of the line is for the reader.

Flags and othersCLC STC CMC CLD STD NOP HLT

On the 8086 a shift or rotate moves by 1 or by CL (mov cl, 4 / shl ax, cl); PUSH takes a register or memory, not a number; and a conditional jump reaches only 128 bytes back or 127 forward: to go further, jump on the opposite condition over a JMP. ASM says so when a program tries otherwise.

The decimal arithmetic instructions (AAA, AAD, AAM, AAS, DAA, DAS), XLAT, LOCK, WAIT and ESC are not supported by the pc86 processor, and ASM rejects them, as it rejects the instructions of later processors (PUSHA, ENTER, MOVZX...).

What ASM Does Not Have

ASM Version 1.00 has no macros, no INCLUDE and no conditional assembly: a program is one source file, assembled into one segment, like a .COM file. Only the .text, .data and .bss sections exist, without attributes (ALIGN=, VSTART=). DD and the other directives for larger data are not supported; use DB and DW.

Return Codes

Function 4Dh returns in AH how the last program ended: 00h normally, 01h by Ctrl-C, 02h by Abort after a critical error, 03h resident. AL is the code the program gave to function 4Ch or 31h, and 0 otherwise. A program ended by COS for an unsupported function returns FFh.
