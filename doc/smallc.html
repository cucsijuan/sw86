This manual describes Small-C Version 1.00, the C compiler for the COS disk operating system on the pc86 personal computer.

Small-C is supplied on the COS System Diskette as the program SMALLC.EXE, with the library CLIB.LIB, the header files (STDIO.H and seven others) and the sample program HELLO.C. Read Chapter 2, "Writing and Running Programs," before you write your first program.

Preface

This manual tells you how to write programs in C for the pc86 personal computer, and how to compile and run them under COS with Small-C, the C compiler of COS. Small-C is a compact C: it has the integer types, pointers, arrays, structures, unions, enumerations, the preprocessor and a library of functions for files, strings and memory, and it makes small, fast programs that can reach every part of the machine — its ports, its memory, its interrupts, and assembly language written inside the C program itself.

This is not a tutorial on the C language. It assumes that you know C, or are learning it from a textbook, and that you know how to use COS: how to start it, how to name files and how to use the text editor, EDIT. These are described in the COS User's Guide. What this manual describes is the C that Small-C accepts, what it leaves out, and what is special to the pc86.

  • If you are new to Small-C, read Part One, Chapters 1 to 4, in order, and try the examples on the computer.
  • If you want to use the machine itself — the keyboard, the speaker, the screen — read Chapter 5. For programs of several files and libraries of your own, read Chapter 6.
  • Part Two is for reference: the library functions, the error messages, and the technical details of the code Small-C makes.

Contents

What Small-C Is

Small-C is a compiler for the C programming language. You write a program as a text file, with the COS editor, EDIT, in a file whose name ends in .C; Small-C translates it into a program of the machine's own language, a file ending in .COM, that you run by typing its name, as you run any other COS program.

C was made for writing programs that are close to the machine: operating systems, editors, compilers, games. Small-C is a compiler of that kind. It has no floating point and no long integers, but it makes compact code, and a C program can do everything an assembly language program can: read and write the ports of the computer, look at any place in memory, call any COS or BIOS service, and even contain instructions of the 8086 processor between its own lines.

Small-C is itself a C program. It is written in the C that it compiles, and it compiles itself.

What You Need

  • A pc86 personal computer with 640 KB of memory and the COS disk operating system.
  • The COS System Diskette. These files on it are for Small-C: SMALLC.EXE, the compiler; CLIB.LIB, the library; the header files CONIO.H, CTYPE.H, DOS.H, IO.H, STDARG.H, STDIO.H, STDLIB.H and STRING.H; and the sample program HELLO.C. Small-C also needs ASM.COM, the assembler, and EDIT.COM, the editor, that are on the same diskette.
  • Room on the diskette for what Small-C writes: a file of assembly language, CCTEMP.ASM, that is larger than the program (about 32 KB for a small one), and the program itself.
  • Patience. Small-C does a great deal of work for a computer with an 8086 processor: to compile the sample program takes about fifty seconds (Chapter 2 tells where the time goes).

A First Program

The System Diskette has the smallest C program, HELLO.C. This is what it looks like:

/* hello.c - the first C program: SMALLC HELLO.C, then HELLO */
#include <stdio.h>

int main(void)
{
    printf("Hello from the 8086, in C!\n");
    return 0;
}

The first line is a comment. The second asks for STDIO.H, the file that tells Small-C about printf, the function that shows text on the screen. Every C program has a function called main, where it starts; this one has a single statement, that calls printf, and ends with return 0, which tells COS that the program worked.

To compile and run it:

A:\>smallc hello.c
HELLO.COM: 3988 bytes

A:\>hello
Hello from the 8086, in C!

A:\>

Small-C shows the name of the program it made and its size. HELLO.COM is now on the diskette; HELLO runs it.

What Small-C Does Not Have

Small-C is C without some of its more advanced parts. It has no long, float or double types (integers are 16 bits, and there is no arithmetic with fractions), no typedef, no pointers to functions, no bit fields, and a structure cannot be passed to a function or returned from it by value. Chapter 3 lists what is missing and what to do instead; each of these things gives an error message when a program uses it, so nothing is silently wrong. Everything else of the language that a program for this computer needs is there.

Running Small-C

Format
SMALLC [options] file ...

Small-C takes one or more files, and the options that tell it what to make of them. The file names must have their extensions, because the extension says what the file is:

The Options

An option begins with a hyphen, or with a slash. Capital and small letters are the same for the letters that name an option, but not in the names that follow -D, -I and -L. Options may be anywhere in the line, among the files.

OptionMeaning
-o nameThe name of the program (or, with -c, of the library). Without it, the program has the name of the first file, with the extension .COM, or .EXE with -e. A name ending in .EXE makes an .EXE, as -e does.
-eMakes an .EXE program: the code has a segment of its own, and so has the data, with room for 64 KB of data, variables, heap and stack (Appendix B).
-cCompiles each .C file to a module in assembly language, with the name of the file and the extension .ASM, and stops there. With -o, all the files are put in one library file, .ASM files too.
-SMakes only the assembly language of the program, a file with the name of the program and the extension .ASM, and does not run ASM.
-Dname[=value]Defines a macro for every file, as #define does. Without a value, the macro is 1. There is no space after -D.
-IdirectoryAdds a directory where #include looks for files (see below). There is no space after -I. Up to three may be given.
-LlibraryAdds a library, a .LIB file, as if it were given among the files, but after all of them. Up to three may be given.
-nDoes not use CLIB.LIB. The program must get its start-up from a library of its own (-L), and its functions too.

When the Program Has a Mistake

Small-C reads all of the program. When a line breaks the rules of the language, Small-C shows the name of the file, the number of the line and what is wrong, and goes on reading, to find more mistakes; it makes no program. This one has two:

/* OOPS.C - a program with mistakes */
#include <stdio.h>

int main(void)
{
    int n;

    n = 3
    printf("%d\n", n + total);
    return 0;
}
A:\>smallc oops.c
oops.c(9): ';' expected
oops.c(9): 'total' is not declared

A:\>

The missing semicolon at the end of line 8 is found only when Small-C sees the printf on line 9, so the message says line 9: when a message does not make sense on its line, look at the line before it. The second message is a result of the first, as often happens: Small-C lost its place, and found 'total' on the way, which was never declared. Correct the first message first, then compile again, and see which of the others are left.

Small-C stops after 20 messages, with "too many errors". The messages are listed in Appendix A. The name of the file is as you typed it; for a mistake in a header file it is the name of that file, so that you know where to go in EDIT: press F5, type the line number, correct it and save.

When Small-C finds a mistake, it writes no program, and the one made by an earlier compilation stays as it was. Small-C ends with return code 1; when it made the program it ends with 0.

Messages From the Link

A program is made of its own modules and of the library functions that it calls. When the program is all read, Small-C looks for the names that are used and are not defined anywhere:

A:\>smallc bad.c
SMALLC: 'twice' is not defined anywhere
SMALLC: 'missing' is not defined anywhere

A:\>

These are the names of functions, or of variables, that the program uses and nobody defines: the spelling is wrong, a file is missing from the line, or a library was not given. Names of C are shown as you wrote them; the names of the assembly language that are not C names are shown with their underscore (Chapter 6). A name that is defined twice is reported too: "_twice is defined in two modules" (see "Programs of Several Files").

Programs of Several Files

A large program is better in several files, each with the functions that belong together. Give them all to Small-C; the program has the name of the first:

/* VEC.H - sums and maximums of arrays of numbers */
int vsum(int *v, int n);
int vmax(int *v, int n);
extern int vcalls;
/* VEC.C - sums and maximums of arrays of numbers */
#include "vec.h"

int vcalls;

int vsum(int *v, int n)
{
    int i, s;

    vcalls++;
    s = 0;
    for (i = 0; i < n; i++)
        s += v[i];
    return s;
}

int vmax(int *v, int n)
{
    int i, m;

    vcalls++;
    m = v[0];
    for (i = 1; i < n; i++)
        if (v[i] > m)
            m = v[i];
    return m;
}
/* DEMO.C - uses the functions of VEC.C */
#include <stdio.h>
#include "vec.h"

int data[] = { 31, 4, 159, 26, 5, 358 };

int main(void)
{
    printf("sum %d, largest %d\n", vsum(data, 6), vmax(data, 6));
    printf("%d calls\n", vcalls);
    return 0;
}

DEMO.COM: 4190 bytes

A:\>demo

A:\>

VEC.H says what VEC.C offers, and both DEMO.C and VEC.C include it. Three rules make the files work together:

  • A function or a variable that other files use is defined in one file only. The other files declare it: a function with its prototype, a variable with extern.
  • A name declared static belongs to its file, and no other file can see it. Two files may each have a static function helper, and they are two different functions.
  • A variable declared without extern in several files, like int counter; in all of them, is one variable. If it is given a value in one of them, that one defines it; if two give it a value, or two files have a function with the same name, the message is "name is defined in two modules". The tidy way is the definition in one file and an extern declaration in the header.

Compiling all the files at each change takes time. Chapter 6 tells how to compile the files that do not change once, and keep them in a library.

.COM and .EXE Programs

A .COM program is made of one segment of 64 KB of the computer's memory, shared by its code, its variables, its heap and its stack. For most programs that is plenty. For one that needs more data, -e makes an .EXE: its code is in a segment, and its data, variables, heap and stack have a segment of 64 KB all to themselves. This program has 60000 bytes of data:

/* BIG.C - more data than a .COM program can hold: make it with SMALLC -e */
#include <stdio.h>

char big[30000];
int more[15000];

int main(void)
{
    int i;
    for (i = 0; i < 30000; i++)
        big[i] = i;
    for (i = 0; i < 15000; i++)
        more[i] = i * 3;
    printf("%u bytes of data, big[29999] = %d, more[14999] = %d\n",
           sizeof(big) + sizeof(more), big[29999], more[14999]);
    return 0;
}

As a .COM program it is too big to start: the stack needs room too. As an .EXE, it works. COS looks for a .COM with the name you type before it looks for an .EXE, so the old BIG.COM is deleted first:

A:\>smallc big.c
BIG.COM: 4100 bytes

A:\>big
Not enough memory

A:\>smallc -e big.c
BIG.EXE: 4180 bytes

A:\>del big.com

A:\>big
60000 bytes of data, big[29999] = 47, more[14999] = -20539

A:\>

An array has from 1 to 32767 elements; keep each array and structure under 32 KB, in a .COM or an .EXE. The code of a program may not be larger than 64 KB, in either. Appendix B describes how both kinds of program use the memory.

Where Small-C Finds Its Files

Small-C is told where it is when COS runs it, and looks for what it needs there:

  • #include "name" looks first in the directory of the file that has the #include, then in the directories given with -I, in order, then in the directory INCLUDE of the directory where Small-C is, then in the directory where Small-C is. #include <name> does the same, but skips the first step. On the System Diskette the header files are in the root directory, next to SMALLC.EXE.
  • CLIB.LIB, the library, is in the directory where Small-C is.
  • ASM.COM is in the directory where Small-C is; if it is not there, in the root directory of the current drive.

So Small-C works from any directory, if you type its whole name: A:\SMALLC. Small-C writes its files, CCTEMP.ASM and the program, in the current directory.

How Small-C Makes a Program

Small-C does not make the .COM file by itself. It writes the whole program as one source in assembly language, in the file CCTEMP.ASM, and then runs ASM, the COS assembler, which makes the program from it and shows its name and size. Then Small-C deletes CCTEMP.ASM. The source holds, one after the other:

  1. the start-up module, which sets the program going and calls main (Appendix B);
  2. the files that you gave, in order: the C sources compiled, the assembly files copied;
  3. the modules of the libraries that the program needs, and those that they need;
  4. the end of the program, where the variables that start as zero are placed.

The computer works at 4.77 megahertz, and Small-C and ASM have much to do: SMALLC HELLO.C takes about 50 seconds, of which about 20 are Small-C reading and compiling and 30 are ASM assembling. A program that prints something, like this one, brings in the library functions that print, and that is most of the time. The compiled program starts at once, and is fast.

The programs that ASM finds mistakes in are those that have assembly language of their own. ASM shows its own messages (Chapter 10 of the COS User's Guide), with the line in CCTEMP.ASM. If you wish to read what Small-C wrote, use -S: it keeps the .ASM file, with the name of the program, and does not run ASM. You can then assemble it yourself with ASM.

The Command Line of a Program

The words typed after the name of a program arrive in main as argc and argv, as the language says: argv[0] is the name of the program with its whole path, argv[1] is the first word, and so on. A word in quotation marks may have spaces inside; the marks are not part of the word. A program may have 24 words, and the whole line may have 127 characters.

/* ARGS.C - shows the words of the command line */
#include <stdio.h>

int main(int argc, char **argv)
{
    int i;

    for (i = 0; i < argc; i++)
        printf("argv[%d] = \"%s\"\n", i, argv[i]);
    return argc - 1;
}

In an expression a char is turned into an int first, with its sign. When an operation has an unsigned operand the operation is unsigned: division, remainder, shifts to the right and comparisons. The results of integer arithmetic that do not fit in 16 bits are cut to 16 bits, without any message.

A decimal constant above 32767, or one that ends in U, is unsigned. A constant with L is an error: there are no long numbers. A character constant like 'A' has the code of the character; the escapes are \n \t \r \a \b \f \v \0, \x followed by hexadecimal digits and \ followed by up to three octal digits. Strings written next to each other are joined into one: "ab" "cd" is "abcd". A string may have up to 299 characters, and each one written in a program is kept separately, in the data of the program, where it can be changed.

/* TYPES.C - the integer types and how they mix */
#include <stdio.h>

int main(void)
{
    char c;
    unsigned char b;
    int i;
    unsigned u;

    c = 200;                    /* char is signed: this is -56 */
    b = 200;
    i = -7;
    u = 65535;
    printf("%d %d %d\n", c, b, (unsigned char)c);
    printf("%d %d %d\n", i / 2, i % 2, i >> 1);
    printf("%u %u %d\n", u >> 1, u + 1, (int)u);
    printf("%d %d\n", i < 1, (unsigned)i < 1);
    printf("%d %d\n", u > 30000, sizeof(int[10]));
    printf("%d %d %d\n", 0x1F, 017, 'A');
    return 0;
}

Declarations

A declaration is as in C: int a, *b, c[10]; declares an int, a pointer to int and an array of ten. Inside a function the declarations must be at the start of a block, before the first statement; Small-C says "declarations go at the start of a block" otherwise. A variable declared in a block is known until the end of the block.

Initial values

  • Variables outside functions, and static variables of functions, start as zero, or with the value given. The value must be constant: numbers and constant expressions, the address of a variable (&x, &table[2], or the name of an array), or a string.
  • Arrays and structures are initialized with braces, as in C, with braces inside braces, with fewer values than elements (the others are zero) and with a last comma. If the size of an array is left out, the values give it. A char array may be initialized with a string, and a char pointer too.
  • Variables of a function (auto) may be initialized with any expression, when they are simple numbers or pointers. An array or structure of a function cannot have an initial value: make it static.
  • One initializer may have up to 40 strings for pointers, with 600 characters in all. A larger table of strings is better in two parts.

Declarators

Pointers and arrays can be combined as in C (an array of pointers is char *names[4]), but parentheses in a declarator are not accepted, so there are no pointers to arrays, nor pointers to functions. An array has at most 8 dimensions. Only the first one may be left out.

Arrays and Pointers

The name of an array, used as a value, is a pointer to its first element. Arrays of arrays are stored row by row.

/* ARRAYS.C - arrays, pointers and strings */
#include <stdio.h>
#include <string.h>

int table[3][4];
char name[] = "Ada";
char *days[] = { "Mon", "Tue", "Wed" };

int main(void)
{
    int i, j, *p;
    char *s;

    for (i = 0; i < 3; i++)
        for (j = 0; j < 4; j++)
            table[i][j] = i * 10 + j;
    p = &table[1][0];
    printf("%d %d %d\n", table[2][3], p[2], *(p + 5));
    printf("%d %d\n", sizeof(table), sizeof table[0]);
    s = name;
    while (*s)
        printf("%c.", *s++);
    printf(" %d %s\n", strlen(name), days[2]);
    printf("%d\n", &table[2][0] - &table[0][0]);
    return 0;
}

Structures, Unions and Enumerations

A structure is the members one after another, byte by byte, without any space between them; a union takes the size of its largest member. A structure may be assigned to another of the same type, and used through pointers (->), but it cannot be passed to a function or returned from one: pass its address. The tag of a structure may be used inside it, as the type of a pointer, for lists and trees. The names of an enumeration are int constants, counted from 0 or from the value given.

/* STRUCTS.C - structures, unions and enumerations */
#include <stdio.h>

enum color { RED, GREEN = 5, BLUE };

struct point {
    int x, y;
};

struct item {
    char name[8];
    struct point where;
    enum color shade;
};

union word {
    unsigned w;
    struct { unsigned char lo, hi; } b;
};

struct item items[2] = {
    { "key", { 3, 4 }, GREEN },
    { "lamp", { 10, 20 }, BLUE }
};

void move(struct item *it, int dx, int dy)
{
    it->where.x += dx;
    it->where.y += dy;
}

int main(void)
{
    struct item copy;
    union word w;

    copy = items[1];
    move(&copy, -1, 5);
    printf("%s %d,%d %d\n", copy.name, copy.where.x, copy.where.y, copy.shade);
    printf("%s %d,%d\n", items[1].name, items[1].where.x, items[1].where.y);
    w.w = 0x1234;
    printf("%x %x %d %d\n", w.b.lo, w.b.hi, sizeof(struct item), sizeof(union word));
    return 0;
}

Functions

A function may be written in the new way, with the types in the parentheses, or the old way, with the names in the parentheses and the types after them. A prototype may leave out the names of the parameters; a definition may not. A function with no value is void, and one with no parameters has (void), or empty parentheses. A function may have up to 32 parameters.

Small-C does not compare the arguments of a call with the prototype: neither their number nor their types. A call with the wrong number of arguments compiles, and does nonsense when it runs; be careful. The prototype is used for the type of the value that the function returns. A function that is called before it is declared is taken for one that returns int, so declare functions that return anything else before they are used.

Variable arguments are written with ... and read with the macros of STDARG.H. The arguments are words, so a char is read as an int.

A macro without parameters is replaced by its text wherever its name is found as a word, outside of strings. What a C Program Can Reach

Ports

inp and outp read and write a byte at a port of the computer; inpw and outpw, a word. This program makes a sound with the timer and the speaker, as Appendix D of the COS User's Guide describes them, and waits for 9 ticks of the clock before stopping it.

/* TICKS.C - ports, memory and interrupts: a beep and a clock */
#include <stdio.h>
#include <dos.h>
#include <conio.h>

unsigned ticks(void)
{
    return peek(0, 0x46C);          /* the BIOS counts 18.2 ticks a second */
}

void wait(int n)
{
    unsigned t;

    t = ticks();
    while (ticks() - t < n)
        ;
}

void tone(int divisor)
{
    outp(0x43, 0xB6);               /* timer 2, a square wave */
    outp(0x42, divisor & 255);
    outp(0x42, divisor >> 8);
    outp(0x61, inp(0x61) | 3);      /* the speaker on */
}

void quiet(void)
{
    outp(0x61, inp(0x61) & 0xFC);
}

int main(void)
{
    struct REGS r;
    int n;

    r.ax = 0x3000;                  /* COS function 30h: the version */
    intdos(&r, &r);
    printf("COS version %d.%d\n", r.ax & 255, r.ax >> 8);
    tone(2712);                     /* about 440 Hz */
    wait(9);
    quiet();
    printf("Counting seconds; press a key to stop.\n");
    for (n = 1; n <= 5 && !kbhit(); n++) {
        wait(18);
        printf("%d second%s\n", n, n == 1 ? "" : "s");
    }
    if (kbhit())
        getch();
    return 0;
}

Interrupts

int86(n, &in, &out) loads the registers AX, BX, CX, DX, SI and DI from the structure in, runs INT n, and puts the registers that the service gave back into out; the structure has the carry flag too, in cflag (1 when the service failed, with an error code in ax). intdos does the same for INT 21h, the COS services. The two structures may be the same one, as in the examples. DS is the data segment of the program, so a pointer that is given in DX, SI or DI is understood by the service; the other segment registers are not set.

The number of the interrupt is written into the code of int86, so it may be any variable.

The Keyboard and the Screen

printf and the other functions of STDIO.H write on the screen and read the keyboard line by line, as COS does it. For a program that wants a key at once, without waiting for Enter, CONIO.H has getch, that waits for a key and shows nothing, getche, that shows it, and kbhit, that tells whether a key is waiting, so that a program can do something else until it is. Keys without a character, like the function and cursor keys, come as two values: 0, and then a code (Appendix B of the COS User's Guide). getch does not stop the program when you press Ctrl-C: it is the character 3, and the program must end by itself. putch and cputs write characters just as they are; end a line with both \r and \n there.

stdout is written at the end of each line, and before the program waits for the keyboard. A program that writes a part of a line, and then waits with getch, should call fflush(stdout) first.

Assembly Language in C

Lines between #asm and #endasm go into the program as they are. The lines are not looked at by the preprocessor; they are limited to 767 characters in all. There are two ways to use them.

Inside a function, the lines become part of its code. BP holds the frame of the function: the first parameter is at [bp+4], the second at [bp+6], and so on, and what the function returns is in AX. In the first function below there is no return statement; the value that is in AX when the function ends is the result.

At the top level of a file, the lines are a function (or data) of their own. Write section .text first, give the label with an underscore, as in _swapb, and tell Small-C its name with a line ;#def _swapb, so that the program can find it (Chapter 6). Here the arguments are at [sp+2], [sp+4]...: BX is the easy way to read them. A function must leave BP, SI, DI, DS and SS as it found them (Appendix B).

/* ASMDEMO.C - assembler inside a C program */
#include <stdio.h>

/* A whole function in assembler, at the top level of the file.
   The arguments are at [sp+2], [sp+4]...; the result goes in AX. */
#asm
section .text
;#def _swapb
_swapb:
    mov bx, sp
    mov ax, [bx+2]
    xchg al, ah
    ret
#endasm

unsigned swapb(unsigned x);

/* A few instructions inside a C function. BP holds the frame, so the
   first argument is at [bp+4]; the value of the function is AX. */
int triple(int x)
{
#asm
    mov ax, [bp+4]
    mov cx, ax
    add ax, ax
    add ax, cx
#endasm
}

int main(void)
{
    printf("%x %d\n", swapb(0x1234), triple(14));
    return 0;
}

Memory for Data

malloc takes memory from the heap, which goes from the end of the variables of the program to 2 KB below the stack, and free gives it back. The variables that are not initialized start as zero; the memory that malloc gives does not (use calloc for that).

The Calling Convention

This is what to know to write functions in assembly language that C can call, or to call C from assembly language.

  • The caller pushes the arguments, each as a word, from the last to the first, calls the function, and takes the arguments off the stack itself (ADD SP, n). A char argument is pushed as an int. At the start of the function, [sp] is the return address and [sp+2] the first argument.
  • A function that uses its stack frame begins with PUSH BP and MOV BP, SP. Then the first parameter is at [bp+4], the second at [bp+6], and so on; the variables of the function are below BP, at [bp-2], [bp-4]...
  • The value is returned in AX.
  • BP, SI, DI, DS, ES and SS must be as they were when the function ends. AX, BX, CX and DX may be changed. The direction flag is clear, and must be left so.
  • A function of C that is called with the wrong number of arguments cannot know it; the stack is put right by the caller, so it keeps its balance, but the function reads what is not there.

Data

  • int, unsigned, pointers and enumerations are 2 bytes, low byte first. char is 1 byte.
  • The members of a structure follow each other with no padding; a structure may begin at any address. The members of a union all begin at its start. An array of arrays is stored with the last index changing fastest.
  • A string is a series of bytes with a zero after it, in the data of the program. The data that have an initial value come first, then the variables that start as zero, which are not in the file of the program, but placed after it when it starts, and set to zero.

Memory of a .COM Program

The program is loaded at offset 0x100 of a segment, after its PSP, and its code, its initialized data and its other variables follow, in that order. The program asks COS for 64 KB and gives back the rest of memory. The stack starts at the top of the segment. The heap goes from the end of the variables, up, to 2 KB below the stack pointer at the start.

Memory of an .EXE Program

An .EXE has a header with one relocation, which sets the data segment, and then its code. The code is one segment, up to 64 KB, as in a .COM. The data segment is another, after the code (on a boundary of 16 bytes): it holds the initialized data, the variables that start as zero, the heap, and the stack, which begins at the top of the segment, offset 0, wrapped, and goes down. The program asks for the memory it needs, at least the variables and 4 KB of stack, and gives back what it does not use of the rest. The heap stops 2 KB below the stack, as in a .COM. CS and DS are different segments, so the data may be the whole 64 KB, less the stack.

  • find looks a word up and makes a new entry when it is new, returning a pointer to the entry, so main can count it with e->count++.
  • getword reads letters from the file with getc and ctype's isalpha, and makes them small with tolower.
  • sort uses structure assignment: a structure cannot be passed to a function, but may be copied.
  • The percentage is worked out as an unsigned number, so that count * 100 does not overflow an int.

The Listing

/* WORDS.C - counts the words of a text file and lists the commonest.
 *
 *   WORDS file [count]
 *
 * A word is a run of letters (and apostrophes); capitals count as small
 * letters. Make it with: SMALLC WORDS.C   (or SMALLC -DMAXWORDS=500 WORDS.C)
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#ifndef MAXWORDS
#define MAXWORDS 300            /* different words kept */
#endif
#define MAXLEN 20               /* longer words are cut */

struct entry {
    char *word;
    int count;
};

static struct entry table[MAXWORDS];
static int used;                /* entries of table in use */

/* The entry of a word, made if it is new; 0 when there is no room. */
static struct entry *find(char *w)
{
    int i;

    for (i = 0; i < used; i++)
        if (strcmp(table[i].word, w) == 0)
            return &table[i];
    if (used == MAXWORDS)
        return 0;
    table[used].word = strdup(w);
    if (table[used].word == 0)
        return 0;
    table[used].count = 0;
    return &table[used++];
}

/* Reads the next word of f into w: its length, or 0 at the end. */
static int getword(FILE *f, char *w)
{
    int c, n;

    do
        c = getc(f);
    while (c != EOF && !isalpha(c));
    n = 0;
    while (c != EOF && (isalpha(c) || c == '\'')) {
        if (n < MAXLEN)
            w[n++] = tolower(c);
        c = getc(f);
    }
    w[n] = 0;
    return n;
}

/* Puts the table in order of count, the commonest first. */
static void sort(void)
{
    int i, j;
    struct entry e;

    for (i = 1; i < used; i++) {
        e = table[i];
        for (j = i - 1; j >= 0 && table[j].count < e.count; j--)
            table[j + 1] = table[j];
        table[j + 1] = e;
    }
}

int main(int argc, char **argv)
{
    FILE *f;
    char w[MAXLEN + 1];
    struct entry *e;
    int i, top, total, lost;

    if (argc < 2) {
        printf("usage: WORDS file [count]\n");
        return 1;
    }
    f = fopen(argv[1], "r");
    if (f == 0) {
        printf("WORDS: cannot open %s\n", argv[1]);
        return 1;
    }
    top = argc > 2 ? atoi(argv[2]) : 10;
    total = 0;
    lost = 0;
    while (getword(f, w)) {
        total++;
        e = find(w);
        if (e)
            e->count++;
        else
            lost++;
    }
    fclose(f);
    sort();
    printf("%d words, %d different\n", total, used);
    for (i = 0; i < used && i < top; i++)
        printf("%-12s %4d %3u%%\n", table[i].word, table[i].count,
               (unsigned)table[i].count * 100 / total);
    if (lost)
        printf("%d words were not counted: the table is full\n", lost);
    return 0;
}
